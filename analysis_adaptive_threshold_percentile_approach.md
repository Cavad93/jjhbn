# Анализ: Процентильный подход для Adaptive Threshold

## 📊 ТЕКУЩАЯ РЕАЛИЗАЦИЯ

### Как работает сейчас:

**Базовый порог:**
- `< 500 сделок`: фиксированный `0.5` (холодный старт)
- `< 50 сделок`: `BASE_THRESHOLD_INITIAL = 0.65`
- `≥ 50 сделок`: `BASE_THRESHOLD_TRAINED = 0.58`

**Плавные корректировки (delta: -0.05 до +0.10):**
1. **Win Rate** (WR 0.35-0.70): от +0.08 до -0.05
2. **Calibration Error** (0.01-0.10): от 0.00 до +0.04
3. **Частота сделок** (0-20/час): от -0.02 до +0.03
4. **Тренд WR** (WR_50 vs WR_200): от +0.05 до -0.02
5. **Просадка** (0-20%): от 0.00 до +0.06

**Финальный порог:** base_threshold + delta, ограничен `[0.5, 0.8]`

## 🎯 ПРЕДЛОЖЕННЫЙ ПОДХОД: ПРОЦЕНТИЛЬ 90%

### Суть предложения:

**Каждые 4 часа пересчитывать threshold как процентиль 90% от распределения:**

**Группа А: Позиции что ПРОШЛИ отбор (открылись)**
```
p_up для LONG: [0.62, 0.68, 0.71, 0.65, 0.73, ...]
p_down для SHORT: [0.67, 0.64, 0.69, ...]
```

**Группа Б: Позиции что НЕ ПРОШЛИ отбор (отклонены)**
```
p_up для LONG: [0.52, 0.48, 0.54, 0.51, ...]
p_down для SHORT: [0.53, 0.49, ...]
```

**Расчет threshold:**
```python
# Объединяем все вероятности (прошедшие + отклоненные)
all_probabilities = группа_А + группа_Б

# Берем процентиль 90%
threshold = np.percentile(all_probabilities, 90)
```

---

## ⚖️ АНАЛИЗ ПОДХОДА

### ✅ АРГУМЕНТЫ ЗА:

#### 1. **Data-Driven** (основано на реальных данных)
- Threshold автоматически адаптируется к фактическому распределению вероятностей
- Не нужно вручную подбирать коэффициенты корректировок
- Самонастраивающаяся система

#### 2. **Автоматическая адаптация к рынку**
```
Спокойный рынок (мало сигналов):
  Все вероятности: [0.48, 0.51, 0.53, 0.56, 0.59, 0.62]
  Percentile 90% = 0.60 → более низкий порог

Волатильный рынок (много сигналов):
  Все вероятности: [0.62, 0.65, 0.68, 0.71, 0.73, 0.76]
  Percentile 90% = 0.74 → более высокий порог
```

#### 3. **Защита от overtrading**
- Процентиль 90% автоматически отсекает 90% сигналов
- Берем только самые уверенные 10% возможностей
- Естественная защита от "торговли ради торговли"

#### 4. **Простота и прозрачность**
- Легко объяснить: "берем топ-10% по уверенности"
- Легко визуализировать распределение
- Понятная метрика для отладки

#### 5. **Снижает influence устаревших данных**
- Пересчет каждые 4 часа → свежие данные
- Реагирует на изменения рынка быстрее, чем накопленная статистика WR

---

### ❌ АРГУМЕНТЫ ПРОТИВ:

#### 1. **КРИТИЧНО: Холодный старт**
```python
# Первые 1-2 цикла (8 часов)
Группа А (открытые): []  # Пусто! Еще не открыли
Группа Б (отклоненные): [0.48, 0.51, 0.52]
→ Percentile 90% = 0.52 ???

# Недостаточно данных для стабильного процентиля
# Нужно минимум 30-50 точек для надежного 90-процентиля
```

**Решение:** Первые 500 сделок оставить текущий подход (threshold=0.5)

#### 2. **Зависимость от качества модели**
```
Модель дает низкие вероятности (не уверена):
  Все p_up: [0.48, 0.50, 0.52, 0.53]
  Percentile 90% = 0.53 → низкий порог → много сделок

Модель дает высокие вероятности (overconfident):
  Все p_up: [0.82, 0.85, 0.88, 0.91]
  Percentile 90% = 0.90 → слишком высокий порог → 0 сделок
```

**Это проблема калибровки модели, а не threshold!**

#### 3. **Не учитывает РЕЗУЛЬТАТЫ позиций**
```python
# Процентиль смотрит только на ВХОДНЫЕ вероятности
# НЕ смотрит на то, сработали ли позиции по TP или SL

Пример:
  Position A: p_up=0.72 → закрылась по SL (-10%) ❌
  Position B: p_up=0.64 → закрылась по TP (+9%) ✅

# Percentile 90% выберет Position A, но она убыточная!
```

**Текущий подход лучше:** он учитывает win rate, т.е. РЕЗУЛЬТАТЫ сделок

#### 4. **Игнорирует контекст (просадка, тренд WR)**
```python
# Сценарий: Просадка -15%, WR падает с 60% до 45%
# Нужно: ПОВЫСИТЬ порог (быть осторожнее)
# Но процентиль: может СНИЗИТЬ порог если вероятности низкие

# Текущий подход учитывает:
dd_delta = +0.06 при drawdown=20%
wr_delta = +0.08 при WR=35%
→ Автоматически повышает порог при проблемах
```

#### 5. **Проблема "moving target"**
```python
# Цикл 1: threshold = 0.65
#   Открыли позиции с p_up > 0.65
#   Отклонили позиции с p_up < 0.65

# Цикл 2: threshold = 0.72 (процентиль вырос)
#   Теперь позиции с p_up=0.68 не откроются
#   Но в цикле 1 они бы открылись!

# Непредсказуемость: одинаковые сигналы → разные решения
```

#### 6. **Не защищает от overtrading в волатильности**
```python
# Волатильный рынок: много сигналов с высокими p_up
# Percentile 90% = 0.75
# Но все равно может быть 20-30 сигналов > 0.75!

# Текущий подход: freq_delta повышает порог при >20 сделок/час
# Это ЛУЧШЕ защищает от overtrading
```

## 🎨 ГИБРИДНЫЕ ПОДХОДЫ

### ✅ ВАРИАНТ 1: Percentile + Context (РЕКОМЕНДУЮ)

```python
def get_adaptive_threshold_v3(
    all_probabilities: List[float],  # Все p_up за последние 4 часа
    opened_positions: List[Position],  # Позиции что открылись
    rejected_signals: List[Signal],   # Сигналы что отклонили
    recent_wr: float,                 # Win rate
    current_drawdown: float,          # Просадка
    total_closed: int
) -> float:

    # === ШАГ 1: Базовый percentile ===
    if len(all_probabilities) >= 30:
        # Используем percentile как BASE, а не как финал
        base_threshold = np.percentile(all_probabilities, 85)  # 85%, не 90%
    else:
        # Холодный старт
        base_threshold = 0.58

    # === ШАГ 2: Корректировки по контексту ===
    delta = 0.0

    # Win Rate (текущая логика)
    if recent_wr < 0.45:
        delta += 0.05  # Повышаем при плохом WR
    elif recent_wr > 0.65:
        delta -= 0.03  # Снижаем при хорошем WR

    # Просадка (текущая логика)
    if current_drawdown > 0.15:
        delta += 0.06  # Осторожность при просадке
    elif current_drawdown > 0.10:
        delta += 0.04

    # === ШАГ 3: Quality Check ===
    # Проверяем, насколько хорошо работают позиции выше percentile
    if total_closed >= 100:
        # Считаем WR позиций с p_up > base_threshold
        high_prob_positions = [p for p in opened_positions if p.entry_prob > base_threshold]
        high_prob_wr = calculate_wr(high_prob_positions)

        # Если даже высокие вероятности не работают → повышаем порог
        if high_prob_wr < 0.50:
            delta += 0.08  # Модель плохо калибрована

    # === ШАГ 4: Финал ===
    threshold = base_threshold + delta
    threshold = max(0.5, min(threshold, 0.8))

    return threshold
```

**Преимущества:**
- ✅ Data-driven: percentile адаптируется к рынку
- ✅ Context-aware: учитывает WR, просадку, качество модели
- ✅ Защита: корректировки защищают от просадок и overtrading
- ✅ Гибкость: реагирует на изменения быстрее

### ✅ ВАРИАНТ 2: Dynamic Percentile (альтернатива)

```python
def get_adaptive_threshold_v4(
    all_probabilities: List[float],
    recent_wr: float,
    current_drawdown: float
) -> float:

    # Процентиль сам АДАПТИРУЕТСЯ в зависимости от ситуации

    # Базовый процентиль: 85%
    percentile_value = 85

    # === АДАПТАЦИЯ ПРОЦЕНТИЛЯ ===

    # Win Rate влияет на селективность
    if recent_wr < 0.45:
        percentile_value += 5  # 90% - более селективно
    elif recent_wr > 0.65:
        percentile_value -= 5  # 80% - менее селективно

    # Просадка влияет на осторожность
    if current_drawdown > 0.15:
        percentile_value += 8  # 93% - очень селективно
    elif current_drawdown > 0.10:
        percentile_value += 5  # 90%

    # Ограничиваем [75, 95]
    percentile_value = max(75, min(percentile_value, 95))

    # Считаем threshold
    if len(all_probabilities) >= 30:
        threshold = np.percentile(all_probabilities, percentile_value)
    else:
        threshold = 0.58

    # Ограничиваем
    threshold = max(0.5, min(threshold, 0.8))

    return threshold
```

**Преимущества:**
- ✅ Еще проще: один параметр (percentile) вместо множества delta
- ✅ Интуитивно: "в хорошие времена берем топ-20%, в плохие - топ-5%"
- ✅ Data-driven + context-aware

### ✅ ВАРИАНТ 3: Dual Threshold (самый продвинутый)

```python
def get_dual_adaptive_threshold(
    opened_positions_probs: List[float],    # p_up позиций что открылись
    rejected_signals_probs: List[float],    # p_up сигналов что отклонили
    opened_positions_results: List[bool],   # True=win, False=loss
    recent_wr: float,
    current_drawdown: float
) -> float:

    # === ПОДХОД: Ищем ОПТИМАЛЬНУЮ ГРАНИЦУ между успехом и неудачей ===

    # Разделяем открытые позиции на wins и losses
    winning_probs = [p for p, result in zip(opened_positions_probs, opened_positions_results) if result]
    losing_probs = [p for p, result in zip(opened_positions_probs, opened_positions_results) if not result]

    # Находим медиану для каждой группы
    if len(winning_probs) >= 10 and len(losing_probs) >= 10:
        win_median = np.median(winning_probs)
        loss_median = np.median(losing_probs)

        # Оптимальный порог - между ними, но ближе к win
        # Например: win_median=0.68, loss_median=0.58
        # threshold = 0.65 (ближе к win для осторожности)
        threshold = loss_median + 0.7 * (win_median - loss_median)
    else:
        # Недостаточно данных → fallback на percentile
        all_probs = opened_positions_probs + rejected_signals_probs
        threshold = np.percentile(all_probs, 85) if len(all_probs) >= 30 else 0.58

    # Корректировки по контексту
    delta = 0.0

    if recent_wr < 0.45:
        delta += 0.05
    elif recent_wr > 0.65:
        delta -= 0.03

    if current_drawdown > 0.15:
        delta += 0.06

    threshold = threshold + delta
    threshold = max(0.5, min(threshold, 0.8))

    return threshold
```

**Преимущества:**
- ✅✅✅ Учитывает РЕЗУЛЬТАТЫ позиций (win/loss)
- ✅✅✅ Находит реальную границу между успехом и неудачей
- ✅ Data-driven: основано на фактических исходах
- ✅ Самонастройка: адаптируется к изменению качества модели

**Это самый сильный подход!**

**Почему:**
- Баланс между data-driven и защитой от просадок

- Безопасность через корректировки

**Когда:**
- После 50+ закрытых позиций

### 🥉 ТРЕТЬЕ МЕСТО: Вариант 2 (Dynamic Percentile)

**Почему:**
- Простой и понятный

- Хорош для начала

**Когда:**
- Подходит для любого этапа

**Почему:**
