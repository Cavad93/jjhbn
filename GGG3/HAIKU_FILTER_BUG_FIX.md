# 🐛 Критическое исправление: Haiku Filter Logic Bug

**Дата:** 2025-11-09
**Файл:** `strategy/haiku_analyzer.py:931-1012`
**Функция:** `analyze_and_rank_top20()`

---

## ❌ Проблемы (2 критических бага)

### Проблема #1: Неправильная логика фильтрации (И вместо ИЛИ)

**Описание:**
Haiku filter отклонял **почти все позиции**, даже те, у которых были отличные фундаментальные показатели.

**Корневая причина:**

**Старая логика (НЕПРАВИЛЬНАЯ):**

```python
# Монета одобряется ТОЛЬКО если проходит технический порог
if passes_threshold and haiku_score > 0.6:
    # Оба фильтра
    approved = True
elif passes_threshold:
    # Только техника
    approved = True
else:
    # НЕ прошла технический порог - ОТКЛОНИТЬ! ❌
    continue  # <-- ВОТ БАГ!
```

**Проблема:** Монеты с низким `p_up` (техническая вероятность), но с **отличным `haiku_score`** (фундаментальный анализ), отклонялись полностью!

### Пример бага

```
Монета: SOLUSDT
  - p_up = 0.54 (техническая вероятность)
  - p_threshold = 0.58 (адаптивный порог)
  - haiku_score = 0.85 (отличные фундаментальные показатели!)

Результат: ❌ ОТКЛОНЕНА (потому что 0.54 < 0.58)
```

**Это абсурд!** Haiku нашел монету с отличными новостями/каталистами, но технический фильтр её заблокировал.

---

### Проблема #2: "Skipped" монеты ошибочно проходили фундаментальный фильтр

**Описание:**
Монеты с `haiku_reason="skipped: weak signal"` НЕ анализировались Haiku (пропущены из-за низкого `p_up < 0.35`), но их `haiku_score` (который просто равнялся `p_up`) использовался для фундаментального одобрения!

**Корневая причина:**

```python
# В analyze_batch() (строка 624)
if self._should_skip_analysis(opp):
    opp['haiku_score'] = opp['p_up']  # ← ПРОБЛЕМА!
    opp['haiku_reason'] = "skipped: weak signal"

# Затем в analyze_and_rank_top20() (старая строка 993)
haiku_approved = haiku_score > 0.6  # ← БАГ!
```

**Пример бага #2:**

```
Монета: MATICUSDT
  - p_up = 0.68 (высокий технический скор)
  - Но p_up < MIN_P_UP_FOR_ANALYSIS (0.35) ← ЛОЖЬ, на самом деле ВЫШЕ
  - Или монета была закэширована и пропущена
  - haiku_score = 0.68 (просто копия p_up)
  - haiku_reason = "skipped: weak signal"

Старый код: haiku_score (0.68) > 0.6 → TRUE → монета одобрена как fund_only! ❌
НО ЭТО НЕПРАВИЛЬНО - монета НЕ была проанализирована Haiku!
```

---

## ✅ Решения

### Решение #1: Логика ИЛИ вместо И

**Принцип:** Монета одобряется, если проходит **ХОТЯ БЫ ОДИН** фильтр:
1. Технический (`passes_threshold`) **ИЛИ**
2. Фундаментальный (`haiku_score > 0.6`)

```python
# Проверяем: прошла ли монета хотя бы один фильтр?
if not (passes_threshold or haiku_approved):
    # Не прошла НИ ОДИН фильтр - отклоняем
    continue

# Монета прошла хотя бы один фильтр - определяем финальный скор
if passes_threshold and haiku_approved:
    # Прошла ОБА фильтра
    final_score = confidence * 0.6 + haiku_score * 0.4
    reason = 'tech+fund'
elif passes_threshold:
    # Прошла только технический фильтр
    final_score = confidence
    reason = 'tech_only'
else:
    # Прошла только фундаментальный фильтр ✨
    final_score = haiku_score * 0.9  # С небольшим снижением для осторожности
    reason = 'fund_only'
```

### Решение #2: Проверка на "skipped" и "error" монеты

```python
# В analyze_and_rank_top20() (НОВАЯ строка 993-1005)
haiku_score = opp.get('haiku_score', 0.5)
haiku_reason = opp.get('haiku_reason', '')

# КРИТИЧЕСКОЕ ИСПРАВЛЕНИЕ #2
# Монеты с "skipped" или "error" НЕ были проанализированы Haiku
was_analyzed_by_haiku = 'skipped' not in haiku_reason and 'error' not in haiku_reason
haiku_approved = was_analyzed_by_haiku and (haiku_score > HaikuConfig.SCORE_THRESHOLD_APPROVE)
```

**Почему это правильно:**

- **"Skipped" монеты** не должны проходить фундаментальный фильтр (они вообще не анализировались!)
- **"Error" монеты** (ошибки API) также не должны считаться одобренными
- Такие монеты могут пройти **только технический фильтр**

---

### Почему эти решения правильны?

1. **Haiku теперь работает как задумано**: находит монеты с сильными фундаментальными каталистами
2. **Логика ИЛИ вместо И**: позволяет любому фильтру одобрить позицию
3. **Защита от ложных срабатываний**: "skipped" и "error" монеты НЕ проходят фундаментальный фильтр
4. **Взвешенные скоры**: при прохождении обоих фильтров используется комбинированный скор (60% техника + 40% фундамент)
5. **Консервативность для fund_only**: скор снижается на 10% для осторожности
